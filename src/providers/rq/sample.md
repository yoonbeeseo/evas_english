# Todo List App 요구사항 정의서

## 1. 개요

본 문서는 단일 페이지로 구성된 간단한 Todo List 웹 애플리케이션의 요구사항을 정의한다.  
사용자는 할 일을 입력하고, 완료 상태를 토글하며, 길게 눌러 항목을 삭제할 수 있다.

---

## 2. 목표

- 최소한의 인터랙션으로 할 일 관리
- 모바일/웹 환경 모두에서 직관적으로 사용 가능
- 복잡한 기능 없이 핵심 기능에 집중한 MVP 구현

---

## 3. 앱 구성

- Single Page Application (SPA)
- 페이지 수: 1개
- 주요 구성 요소
  - 입력 영역 (텍스트 입력)
  - Todo 리스트 영역

---

## 4. 기능 요구사항

### 4.1 Todo 추가

- 사용자는 텍스트 입력창에 문장을 입력할 수 있다.
- `Enter` 키를 누르면 Todo가 리스트에 추가된다.
- 빈 문자열은 추가되지 않는다.
- Todo 추가 후 입력창은 비워진다.

---

### 4.2 Todo 완료 처리

- Todo 항목을 **한 번 클릭**하면 완료 상태로 변경된다.
- 완료된 Todo는 시각적으로 구분되어야 한다.
  - 예: 취소선, 흐린 색상 등
- 완료된 Todo를 **다시 한 번 클릭**하면 미완료 상태로 복구된다.

---

### 4.3 Todo 삭제

- Todo 항목을 **오랫동안 누르면 (Long Press)** 삭제 확인 UI가 표시된다.
- 삭제 확인 메시지 예시:
  - "이 할 일을 삭제할까요?"
- 사용자가 삭제를 확정하면 해당 Todo는 리스트에서 제거된다.
- 취소 시 아무 동작도 하지 않는다.

---

## 5. 사용자 인터랙션 요약

| 동작                 | 결과      |
| -------------------- | --------- |
| 텍스트 입력 후 Enter | Todo 추가 |
| Todo 1회 클릭        | 완료 처리 |
| Todo 2회 클릭        | 완료 취소 |
| Todo 길게 누르기     | 삭제 확인 |
| 삭제 확인            | Todo 삭제 |

---

## 6. 상태 정의

각 Todo는 다음 상태를 가진다.

- `id`: 고유 식별자
- `text`: Todo 내용
- `completed`: 완료 여부 (boolean)

---

## 7. 제약 사항

- 로그인 기능 없음
- 서버 연동 없이 클라이언트 상태로만 관리 가능
- 디자인은 기능 구현 이후 최소 수준으로 적용

---

## 8. 추후 확장 가능 항목 (Optional)

- Todo 전체 삭제
- 완료 / 미완료 필터
- 드래그로 순서 변경
